# 3D 전투 무대 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 빈 `index.html` 위에 로우폴리 3D 전투 무대와 최소 평면 화면을 만들어, 층 고르기 → 손님 → 전투(합·책 낙하·등급 연출) → 결과가 휴대폰 가로에서 한 바퀴 돌게 한다.

**Architecture:** 규칙은 `js/core/*`(일반 `<script>`, 전역 `Game`) 그대로 둔다. 그 위에 ES 모듈 두 층을 얹는다. `js/stage/*`는 three.js 캔버스로 규칙을 모르고 `stage.play(ev)` 연출만 하고, `js/ui/*`는 DOM 화면으로 `Game`을 불러 상태를 그리고 교환 이벤트를 무대에 넘긴다. 무대는 맨 아래 배경층, UI는 그 위다.

**Tech Stack:** three.js 0.180.0(저장소에 넣음, importmap), KayKit Character Pack: Adventurers 1.0(CC0, glTF), `@gltf-transform/cli` 4.5.1(에셋 줄이기, 개발용), WebAudio 합성 효과음, Playwright(`playwright-core`) 테스트.

**Spec:** `docs/superpowers/specs/2026-11-18-3d-stage-design.md`

## Global Constraints
- 빌드 도구 없음. GitHub Pages가 저장소 루트를 그대로 올린다. 외부 CDN에 의존하지 않는다(three.js·모델 모두 저장소 안).
- 기준 화면 844×390(가로), 390×844(세로)도 지원. 가로에 한 변경은 세로에도 똑같이.
- 글꼴은 Pretendard, Space Grotesk만 쓴다(`assets/fonts/fonts.css`). 세리프·궁서체 금지.
- 막는 팝업 금지(`alert`/`confirm`/모달 없음). 결과·소각 안내는 80% 이상 불투명한 검은 전체 화면이나 별도 카드.
- 연출: 탭 = 남은 교환 빨리 감기, 길게 누르기 = 막 끝까지 건너뛰기. 합 한 번 기본 1.0초, 최대 1.6초.
- 전투 정보 UI(주사위, 체력·흐트러짐 막대, 대상 화살표, 손패, [개막], 상태판) 겹침 0건. 무대·캐릭터는 UI 뒤로 가도 된다. 캐릭터는 키우지 않는다.
- 렌더러 픽셀 비율 ≤ 1.5, 실시간 그림자 없음(둥근 그림자 판). 모델·텍스처 내려받기 총량 ≤ 3MB.
- 에셋은 CC0 등 라이선스가 분명한 것만 쓰고 `CREDITS.md`·`LICENSES.md`에 적는다. Project Moon 에셋과 Ruina 화면 생김새 모방은 금지.
- 규칙 테스트 `node tests/run.mjs core libs mbdata sim`은 매 작업 뒤에도 통과해야 한다.
- 커밋 메시지는 한국어, 사용자 입장에서 쓴다. 이 브랜치(`claude/game-ui-ux-redesign-4l6p7o`)에만 커밋한다. `main` 배포는 큐 양이 확인한 뒤에 한다.

## Review Focus
1. WebGL이 없거나 모델 내려받기가 실패한 기기 → 무대 없이(평면 배경) 전투가 끝까지 진행된다. 테스트는 Task 4.
2. 전투 중 [개막] 두 번 누르기, 연출 중 손패·문제 누르기 → 막이 두 번 처리되지 않는다. 테스트는 Task 6.
3. 세로 390×844와 적 3명 + 사서 3명 → 전투 UI가 겹치지 않고 캐릭터가 화면 안에 있다. 테스트는 Task 8.
4. 한 교환 안에서 적이 쓰러지고 같은 막에 그 적을 노린 다른 교환이 남음(`kind:"skip"`) → 책은 한 번만 떨어지고 연출이 멈추지 않는다. 테스트는 Task 5.
5. 패배(사서 전멸) → 결과 화면으로 가고 다시 접대·층으로 돌아갈 수 있다. 테스트는 Task 6.

    - 동작 고르기: 공격 주사위 종류로 참격=`1H_Melee_Attack_Slice_Diagonal`, 관통=`1H_Melee_Attack_Stab`, 타격=`2H_Melee_Attack_Chop`, 사서가 마법형 모델이면 `Spellcast_Shoot`. 방어=`Block`→`Block_Hit`, 회피=`Dodge_Backward`, 맞음=`Hit_A`/`Hit_B` 번갈아, 쓰러짐=`Death_A`, 승리 마지막=`Cheer`.
    - 합(`clash`): 양쪽이 가운데로 `Running_A`(0~30%) → 부딪침(40%: 불꽃, 히트스톱 70ms, 카메라 흔들림) → 진 쪽 밀려남 → 제자리로 돌아감. 일방 공격(`one-sided`)은 공격자만 달려간다.
    - `result.dead`에 적이 있으면: 쓰러짐 → 조각 흩어짐 → 책 낙하(표지 텍스처 `bookCoverSrc(guest)`). `final:true`(이 교환으로 승리)면 책 낙하를 1.6배 길게 하고 사서 `Cheer`.
    - 흐트러짐(`result.staggered`): 비틀거림(`Hit_B`)과 머리 위 별 고리를 다음 막까지 둔다.
  - `Stage.finishNow() -> void`: 진행 중인 `play`를 즉시 끝내고(각 유닛 최종 자세) resolve한다. 길게 누르기용.
  - 등급 연출: 이 교환에 쓰인 책장 중 가장 높은 등급(`PAGE_BY[card].rarity`, 적 카드는 `cardInfo`의 rarity, 없으면 `"N"`).
    - N: 기본
    - R: 불꽃 2배, 색 강조
    - SR: 맞기 직전 0.25초 클로즈업 + 주변 40% 어둡게
    - SSR: 화면 70% 어둡게 + 클로즈업 + 맞는 순간 0.4배속 0.3초 + 큰 고리 이펙트
    - `fast`면 SR·SSR도 클로즈업 없이 이펙트만 낸다.
  - `fx.js`: `export function registerFx(pageId: string, fn: (ctx)=>Promise<void>)`. 등록된 책장이면 등급 연출 대신 이 함수를 쓴다. `ctx = {stage, ev, a:Figure, b:Figure|null, fast, hitAt:Promise}`.
