# 적 모델 다양화 (괴물·동물·로봇·유령·슬라임) — 설계

2026-11-25 · 큐 양 요청

## 왜
지금 적은 전부 KayKit 사람 모험가 5종(기사·바바리안·마법사·도적·두건 도적)이라 전투가 단조롭다.
적은 사람이 아니어도 되니 꼭두각시·괴물·동물 등으로 등장시켜 **보기에 다양하게** 만든다.
개념과 어울리면 좋지만 필수는 아니다(큐 양: "비효율적이면 다양화만 이뤄내도 됨").

## 목표 / 하지 않을 것
- 목표: 앞으로 만드는 적(우두머리 손님 포함)이 사람·해골·꼭두각시·슬라임·괴물·로봇·유령·동물 중에서 모델을 고를 수 있다. 같은 적은 늘 같은 모습.
- 하지 않음: 지금 있는 손님·적의 모습은 바꾸지 않는다.
- 하지 않음: 사서(아군) 모델은 바꾸지 않는다. 장서복 체계도 그대로.
- 하지 않음: 전투 규칙·수치·`body`/`form` 코어 분류는 안 바꾼다(무대 층만 바뀜).
- 실패로 볼 것: 캐릭터가 커져서 전투 UI(주사위·막대·화살표·손패·[개막]·상태판)와 겹침이 생기는 것, 연출이 멈추거나 끊기는 것(동작 없는 모델), 첫 로딩이 눈에 띄게 느려지는 것.

## 정한 것 (큐 양)
- 방법: 다른 뼈대의 괴물·동물 모델을 들여오고, 동작은 모델마다 짝지어 쓴다(3번 안).
- 우두머리 손님도 괴물이 될 수 있다(2번 안: 손님도 섞기).
- 검수: 후보 64종 중 **D9(wolf_cartoon) 제외 63종 사용**. D10~D12(raptor·trex·triceratops)는 조금 키운다.

## 접근 (고른 것과 버린 것)
1. 해골만(KayKit Skeletons, 같은 뼈대) — 싸지만 갈래가 하나뿐. 버림(해골 4종은 3번에 포함).
2. 해골 + 코드로 만든 꼭두각시 — 화풍 일치, 품 중간. 버림(큐 양이 더 다양한 3번 선택).
3. **다른 팩 괴물·동물 + 동작 짝짓기 — 고름.** 다양함이 가장 크다. 대가는 모델마다 동작 이름이 달라 짝짓기 표가 필요하다는 것.

## 에셋
- 출처 1: Quaternius 로우폴리 모델(CC0). npm 패키지 `@netforge/asset-library-files`의 `library/lowpoly/*.glb`(meshopt 압축 사본, NOTICE에 Quaternius·CC0 명시).
  원 사이트(poly.pizza·quaternius.com)는 이 환경 네트워크에서 막혀 있어 npm 경로를 쓴다.
- 출처 2: KayKit Character Pack: Skeletons 1.0(CC0, GitHub) — `Skeleton_Minion/Warrior/Mage/Rogue`. 지금 캐릭터와 뼈대가 같아(41개 뼈 이름 일치) 기존 `anims.glb`를 그대로 쓴다.
- 만들기: `tools/assets/build-monsters.mjs`(`npm run assets:monsters`). 패키지를 받아 meshopt를 풀고, 무대가 쓰는 동작만 남기고, 텍스처 256px, quantize → `assets/models/monsters/<id>.glb`.
  KayKit 해골은 기존 `build-characters.mjs` 방식(동작 제거, `anims.glb` 공유)으로 `assets/models/characters/`에 함께 넣는다.
- `CREDITS.md`·`LICENSES.md`에 두 출처를 적는다(규칙 5).

## 동작 짝짓기
무대가 쓰는 동작 이름(`Idle, Running_A, 공격들, Hit_A, Block_Hit, Dodge_Backward, Death_A, Cheer`)을 모델 클립에 이름 규칙으로 연결한다.
- 공격 ← `Attack|Punch|Bite|Weapon|Headbutt|Shoot|Kick|Slash`(여러 개면 돌아가며)
- 맞음 ← `Hit|HitReact|HitRecieve`, 쓰러짐 ← `Death`, 달리기 ← `Run|Walk|Fly|Jump|Hop`, 대기 ← `Idle|Fly(ing)`
- 막기·피하기 ← 없으면 맞음 / 환호 ← `Yes|Wave|Jump|Dance`, 없으면 대기
- 짝이 없는 동작은 대기 + 살짝 흔들기(코드 tween)로 대신해 **연출이 멈추지 않게** 한다. 빌드 스크립트가 모델별 짝 결과를 출력하고, (구현 때 바뀜: 꼭 있는 건 Idle 뿐. 공격·맞음·쓰러짐이 없는 모델은 코드 동작으로 대신 — 테스트가 0.8초 안에 끝나는지 확인한다.)

## 고르기 — 앞으로 만드는 적에만
**지금 있는 손님·적의 모습은 바꾸지 않는다**(큐 양 2026-11-25). 새 모델은 앞으로 넣을 적이 고를 수 있게만 한다.
- 적 데이터에 겉모습 필드 하나를 더한다: `guest.enemies[i].model = "slime_pink"` 처럼 모델 id. 코어 규칙은 이 값을 읽지 않고 무대로 넘기기만 한다(`look` 에 실어 보냄).
- `model` 이 없으면 **지금과 똑같이** 고른다(사람 5종, `ARCH_MODEL`/`BODY_MODEL`). 그래서 기존 적은 한 픽셀도 안 바뀐다.
- 우두머리(`leader:true`)도 `model` 을 줄 수 있다(큐 양 2번 안: 손님도 섞기).
- 고를 수 있는 모델 목록 = `js/stage/monsters.js` 의 `MONSTERS` 표(id → 파일·기본 키·회전·색 바꾸기 여부·분류). 모르는 id 면 콘솔 경고 후 지금 방식으로.
- `/add-lecture` 스킬과 `docs/content.md` 에 "적 모델 고르기" 절을 넣는다: 분류별 목록(슬라임·괴물·해골·로봇·유령·동물·사람)과 고르는 기준(개념·이름 뜻과 어울리게, 한 무리 안에서 겹치지 않게).
  `npm run check:content` 가 `model` id 가 표에 있는지 검사한다.
- 검수표 그림(분류별 시트)을 `docs/monsters/`에 두어 새 강의 넣을 때 보고 고르게 한다.


## 꼭두각시 (큐 양 2026-11-25 "꼭두각시 적군도 잊지 말고")
맞는 모델이 팩에 없어 **코드로 만든다**. 사람 모델(KayKit 5종 + 해골 4종, 같은 뼈대라 동작 그대로)을 바탕으로:
- 몸 전체를 나무·도자기 색으로 칠한다(손님 팔레트로 옷 부분만 색). 얼굴은 표정 없는 가면처럼 평평한 색.
- 머리 위에 조종 십자 막대(+ 막대 끝에서 머리·두 손으로 내려오는 가는 실 3~5줄, 뼈를 따라 매 프레임 갱신).
- 관절(어깨·팔꿈치·무릎)에 작은 구슬.
- 모델 id: `puppet_knight`, `puppet_mage`, `puppet_rogue`, `puppet_barbarian`, `puppet_hooded`, `puppet_skeleton` … (바탕 모델 + 칠 방식). `MONSTERS` 표의 분류 "꼭두각시".
- 실은 화면 위쪽으로 길게 뻗지 않게 머리 위 짧게(무대 배경층이지만 상태판·주사위와 겹쳐 보이지 않도록 막대 높이는 키 + 0.5 이하).

## 겉모습
- **크기**: 모델별 기본 키 표(작은 날것 ≈1.3, 보통 ≈1.7, 큰 것 ≈2.0). 지금 사람 적 키(따르는 적 1.9×0.9≈1.7, 우두머리 1.9×1.1≈2.1)를 **넘지 않는다**(규칙 4: 캐릭터를 키우지 않는다). 가로 폭이 넓은 모델(용·메카·트리케라톱스)은 폭도 사람 적 자리 폭 안으로 맞춘다. D10~D12는 다른 네 발 짐승보다 한 단계 크게.
- **방향**: 모든 모델의 앞을 +Z로 맞춘다(빌드 때 확인, 아니면 표에서 회전값).
- **색**: 슬라임·블롭 계열은 손님 `palette`로 몸색을 바꾼다(같은 모델도 손님마다 다른 색). 나머지는 원래 색을 두고 손님 팔레트로 살짝(15%)만 물들여 무대 분위기와 맞춘다.
- **우두머리 표시**: 기존 우두머리 고리(`RING.leader`)와 크기 차이 그대로. 손님 장신구(깃펜·저울·등불…)는 몸 옆 자리(지금처럼 obj 기준 위치)를 모델 키·폭에 맞춰 옮겨 단다.
- **무기·책**: 새 모델은 손 뼈 무기를 다루지 않는다(모델에 붙은 것 그대로). `F.hand()`가 쓰이는 곳은 손 뼈가 없으면 몸 앞 위치로 대신한다.
- **얼굴 메우기(입 없애기)**: KayKit 사람 머리에만 적용. 새 모델은 손대지 않는다.

## 로딩
- 새 모델은 **그 전투에 나오는 것만** 받는다(사람 5종 + anims.glb 는 지금처럼 먼저). 받는 동안은 기존 자리표시 도형으로 서 있다가 갈아 끼우지 않고, 전투 시작 전에 기다린다(전투 진입 시 이미 모델 목록을 알 수 있음). 실패하면 사람 모델로 대신(지금의 실패 처리 흐름).
- 63종 합계 크기를 빌드 때 출력한다. 목표: 모델 하나 ≤ 300KB, 한 전투 추가 다운로드 ≤ 1.5MB.
