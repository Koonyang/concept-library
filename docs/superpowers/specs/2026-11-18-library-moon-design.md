# 새 UI — 서랍 메뉴 · 도서관 · 달의 계시 설계 (2026-11-18)

## 1. 왜
새 UI에는 접대(층 → 손님 → 전투 → 결과)만 있다. 성장(책 소각 → 책장·장서복, 덱 편성, 사서·장서복·기프트 장착)과
매일 하는 영단어 퀴즈(달의 계시)는 규칙만 `js/core`에 있고 화면이 없다. 이 둘이 있어야 공부 → 접대 → 성장 → 다시 접대가 돈다.

## 2. 목표 / 안 할 것 / 실패로 치는 것
- 목표
  - 기본 화면 셋을 책갈피 서랍 하나로 오간다: 접대·도서관·계시(큐 양 결정, 나중에 메뉴가 늘어난다).
  - 도서관에서 책 소각, 덱 편성, 사서·장서복·기프트 장착을 다 할 수 있다.
  - 달의 계시를 하루 한 번 할 수 있고, 결과가 그날 첫 접대 보너스로 이어진다(규칙은 이미 있음).
- 안 할 것: 규칙·수치 변경, 뽑기, 장서복별 복장을 실제로 만드는 일(이번엔 **복장을 데이터 한 줄로 붙이는 구조**만 만든다, 5-5).
- 실패로 치는 것: 메뉴를 고르는 데 막는 팝업이 뜨는 것, 장착을 바꿀 때 목록 스크롤이 맨 위로 튀는 것(옛 결정), 전투 화면에 서랍이 보이는 것.

## 3. 제약 (옛 결정 그대로)
- 서랍과 [설정]은 기본 화면(접대·도서관·계시)에만 보인다. 전투·퀴즈 진행·결과에서는 숨긴다.
- 덱은 6~20장, 같은 책장은 2장까지(가진 수 한도). 덱 편성 카드에는 정답·오답 범위를 둘 다 보여 준다.
- 기프트는 사서별, 부위마다 하나. 세트 효과는 지금 착용한 기프트와 관련된 것만 보여 준다. [착용] 표시는 카드 모서리 안쪽에 둔다.
- 소각 결과는 80% 이상 불투명한 검은 화면이나 카드로 보여 주고, 다 모은 책은 목록·개수에서 뺀다(`shownBookCount`).
- 장착을 바꾸거나 덱에 카드를 넣을 때 스크롤 위치는 그대로 둔다.
- 글꼴, 가로 기본·세로 지원, 겹침 규칙은 지금 UI와 같다.

## 4. 고려한 방법
| 결정 | 고른 것 | 이유 |
|---|---|---|
| 메뉴 | **책갈피 서랍**(위쪽 탭 대신) | 큐 양 결정. 전투 밖은 디자인·확장성을 우선한다 |
| 화면 묶음 | 화면 파일을 나눈다: `js/ui/nav.js`(서랍), `library.js`, `moon.js` | `screens.js`가 너무 커지지 않게. 지금 구조(화면 함수 + nav 콜백)를 그대로 쓴다 |
| 도서관 무대 | 3D 무대에 **지금 사서 한 명**을 가운데 세운다(사서 탭에서 고르면 바뀜) | 무대가 배경으로 살아 있고, 누구를 꾸미는지 보인다. 새 에셋은 필요 없다 |
| 계시 무대 | 달빛 열람실 분위기(유닛 없음) | 이름과 맞고 새 에셋이 필요 없다 |

## 5. 설계
### 5-1. 서랍 (`js/ui/nav.js`)
- 왼쪽 위 책갈피 버튼 `#nav-bm`을 누르면 왼쪽에서 서랍 `#nav-drawer`가 미끄러져 나온다. 서랍 밖을 누르거나 Esc를 누르면 닫힌다(확인창 없음).
- 항목: 접대 · 도서관 · 계시(오늘 했으면 "완료" 표시). 지금 화면에 표시를 한다. 항목 목록은 배열 하나로 둬서 나중에 늘리기 쉽게 한다.
- [설정]도 오른쪽 위 책갈피 모양으로 맞춘다(지금 설정 버튼을 그대로 바꿈).

### 5-2. 도서관 (`js/ui/library.js`, `#ui[data-screen="library"]`)
위에 하위 탭 넷: **책 · 덱 · 사서 · 기프트**. 고른 탭은 저장한다.
- **책**: 가진 책(`Game.books.held()`) 목록. 표지·이름·권 수·이 책에서 나오는 것(`Game.books.pool`: 책장·장서복, 가진 수/한도, 확률). [1권 소각] [전부 소각] → `Game.books.burn(gid, n)` → 결과 카드(얻은 것, NEW 표시).
- **덱**: 위쪽에 지금 덱(장 수 n/20, 6장 미만이면 경고 줄), 아래에 가진 책장 목록. 필터는 층·종류(참격/관통/타격/방어/회피)·비용·희귀도. 카드를 누르면 넣기/빼기(`Game.deck.toggle`), 덱 칸의 카드를 누르면 한 장만 뺀다. 카드에 주사위별 정답·오답 범위를 표시한다(`playerDieRange`).
- **사서**: 열린 사서들(다음 사서까지 장서복 몇 개 남았는지). 사서를 고르면(`Game.libs.pick`) 무대의 사서도 바뀐다. [접대에 데려가기] 토글(`toggleParty`, 혼자면 뺄 수 없음). 장서복 목록(가진 것, 효과 글)과 착용(`equipKey`).
- **기프트**: 지금 사서의 부위별 칸(빈칸/착용), 가진 기프트 목록과 착용·해제(`equipGift`). 지금 착용한 것과 관련된 세트 효과, 합계 능력치(`giftTotals`, `bonusLabel`).
- 무대: 지금 사서 한 명을 가운데 세우고 `Idle`(장착을 바꾸면 `Cheer` 한 번).

### 5-3. 달의 계시 (`js/ui/moon.js`, `#ui[data-screen="moon"]`)
`Game.moon`(MoonCore) 흐름을 그대로 쓴다.
1. **intro**: 오늘 단어 수, 제한 시간(단어당 2.5초), [시작]
2. **quiz**: 문제(영→한 / 한→영), 4지선다, 남은 시간 막대, 점수. 정답·오답 표시는 짧게(0.17초 / 0.65초) 하고 그동안 시계를 멈춘다. 시간이 다 되면 `endRound`.
3. **bridge**: 틀린 단어 수. [재현시 하기] / [건너뛰기]
4. **result**: 계시 점수, 재현시 점수, "오늘 첫 접대 기프트 확률 +N%"(`Game.moonBonus()`). 오늘 이미 했으면 처음부터 이 화면.
- 퀴즈 진행 중에는 서랍·설정을 숨긴다(전투와 같음).

### 5-5. 복장 구조 (나중에 최소 작업으로 복장을 만들 수 있게, 큐 양 요청)
- 장서복(`KEY_PAGES[i]`)에 선택 필드 `look`을 둔다. 없으면 지금처럼 사서 기본 모습.
  ```js
  look: { model:"Knight",               // 몸(KayKit 5종 중), 없으면 사서 기본
          cloth:"#3a5a8a",              // 망토·모자 색
          show:["Round_Shield"], hide:["Knight_Helmet"],   // 모델 부품 켜고 끄기(부품 이름은 docs/ui.md 표)
          props:[{name:"lantern", bone:"back", scale:0.6}] } // 공용 소품을 뼈에 붙이기: head | back | hand.l | hand.r
  ```
- 무대는 사서의 장착 장서복 `look`을 읽어 그대로 입힌다. 복장 하나 추가 = 데이터 한 줄, 코드 수정 없음.
- `docs/ui.md`에 모델별 부품 이름 표, 붙일 수 있는 뼈, 소품 이름(`PROP_KIT`)을 적는다.
- 이번에 실제 복장 데이터는 넣지 않는다(테스트용 임시 값만).

### 5-4. 테스트
- `tests/library.test.mjs`: 서랍으로 세 화면 이동, 책 소각(시드 고정) → 결과 카드 → 목록에서 개수 감소, 덱 넣기·빼기와 6장 경고, 장착할 때 스크롤 위치 유지, 사서 고르기 → 무대 사서 바뀜, 기프트 착용·해제.
- `tests/moon.test.mjs`: 계시 한 판(정답·오답 섞기) → bridge → 건너뛰기 → result. 저장에 `save.moon`이 생기고, 다시 들어가면 결과 화면이 바로 나온다.
- 겹침 검사에 도서관·계시 화면을 넣는다(서랍, 탭, 목록, 버튼끼리).
- 기존 9개 테스트도 계속 통과해야 한다.
