# 새 UI — 로우폴리 3D 전투 무대 설계 (2026-11-18)

## 1. 왜 만드나
- 개념의 서고는 큐 양 개인 공부용 게임이다(인강의 약한 개념 = 손님, 퀴즈 + 주사위 합 전투). 전투 방식은 Library of Ruina를 따른다.
- 옛 UI는 "생동감이 없다"는 이유로 전부 내렸다(`legacy/`). 큐 양이 생동감이 없다고 느낀 순간은 셋이다.
  1. **합**할 때
  2. 적이 쓰러지고 **책이 떨어질** 때
  3. **강한 스킬**을 주고받을 때
- 그래서 새 UI의 중심은 이 세 순간이 살아 있는 **로우폴리 3D 전투 무대**다.

## 2. 목표 / 안 할 것 / 실패로 치는 것
- 목표
  - 세 순간이 몸으로 느껴질 것: 달려가 부딪침, 숫자 튐, 짧은 멈칫과 흔들림, 밀려남, 무너짐, 책 낙하.
  - 휴대폰 가로(844×390) 브라우저에서 링크 하나로 바로 열릴 것. 세로(390×844)도 지원.
  - 새 공부 내용(층·손님)을 넣을 때 **새 그림 없이 데이터 몇 줄로** 무대가 생길 것.
- 안 할 것(이번 범위 밖)
  - 로비·도서관·계시 화면의 최종 디자인. 이번에는 게임 한 바퀴(층·손님 고르기 → 전투 → 결과)가 돌 만큼의 평면 화면만 만든다. 최종 디자인은 따로 정한다(빌더 판단으로 정한 범위).
  - 전투 규칙·수치 변경. 규칙은 `js/core/` 그대로다.
  - Godot 같은 게임 엔진 도입.
- 실패로 치는 것(돌아가도 실패)
  - Library of Ruina·Project Moon의 그림·캐릭터·화면 생김새를 옮긴 것처럼 보이는 것. 전투 방식만 따르고 겉모습은 우리 것이다.
  - 휴대폰에서 첫 로딩이 길거나 발열·버벅임이 심한 것.
  - 연출이 템포를 막는 것. 탭하면 빨리 감기, 길게 누르면 건너뛰기가 항상 돼야 한다.
  - 전투 정보 UI끼리 겹치는 것(주사위, 체력·흐트러짐 막대, 대상 화살표, 손패, [개막], 상태판).

## 3. 제약
- 빌드 도구 없는 정적 사이트, GitHub Pages(`main` 루트). 규칙 코어는 일반 `<script>`로 실리는 `js/core/*.js`, 화면은 `Game`(`js/core/api.js`)만 부른다.
- three.js는 저장소 안에 파일로 넣는다(외부 사이트가 막혀도 동작). 버전은 고정한다.
- 에셋은 무료이고 라이선스가 분명한 것만 쓴다(CC0 우선). 출처는 `CREDITS.md`, `LICENSES.md`에 적는다. Project Moon 에셋은 금지. 큐 양이 준 그림(책 표지 8장)은 쓴다.
- 글꼴은 Pretendard, Space Grotesk. 세리프·궁서체는 금지. 막는 팝업도 금지.
- 휴대폰 성능: 픽셀 비율 ≤ 1.5, 실시간 그림자 없음(바닥에 둥근 그림자 판), 조명 몇 개, 에셋 내려받기 총량은 수 MB 이내.

## 4. 고려한 방법과 고른 것
| 결정 | 고려한 것 | 고른 것 · 이유 |
|---|---|---|
| 만드는 도구 | Godot / 웹 + three.js | **웹 + three.js.** 큐 양이 Godot 에디터를 다룰 계획이 없다. 규칙 코어를 그대로 쓰고 로딩이 가볍다. |
| 캐릭터 | 완성 3D 캐릭터 / 코드 도형 조립 / 섞기 | **섞기.** 몸과 동작(달리기·공격·맞기·쓰러지기)은 CC0 리깅 캐릭터(Quaternius, KayKit 등), 손님별 소품·색·크기는 코드로 붙인다. 도형 조립은 예전처럼 생동감이 부족할 위험이 크다. |
| 강한 스킬 연출 | 등급별 / 책장마다 전용 / 섞기 | **섞기.** N·R·SR·SSR 등급마다 연출 단계를 두고, 고른 SR·SSR 몇 장만 전용 연출을 준다. |
| 무대 분위기 | 시안 A 등불 서고 / B 달빛 열람실 / C 잉크와 종이 | **A와 B를 층마다.** 범죄학·형법 층은 등불, 학습법 층(기억·인지)은 달빛. 층 겉모습은 데이터 한 줄로 정한다(5-3). |

## 5. 설계

### 5-1. 층 구조
```
index.html
├─ js/core/*      규칙·데이터·엔진·저장 (지금 그대로, 화면 없음)
├─ js/stage/*     three.js 무대: 장면, 조명·분위기, 캐릭터, 소품, 연출 (DOM UI 모름)
└─ js/ui/*        DOM 화면: 층·손님 고르기, 전투 정보 UI, 결과 (무대 위에 얹힘)
```
- 무대는 화면 맨 아래 배경층(캔버스 하나)이고, 전투 정보 UI는 그 위 DOM이다. 무대·캐릭터는 UI 뒤로 가도 된다. UI끼리는 겹치면 안 된다.
- 무대는 규칙을 모른다. UI가 코어에서 받은 이벤트를 무대에 넘기면, 무대는 그것을 연출하고 끝나면 알린다.

### 5-2. 전투 연출 흐름
- 막 진행은 코어 그대로다(question → assign → resolve). [개막]을 누르면 교환을 하나씩 처리한다.
  코어에 있는 `mbResolveBegin / mbResolveNext / mbResolveEnd`를 `Game.battle`에 열어 쓴다.
- 교환 하나마다 `stage.play(ev, {fast})`가 Promise를 돌려준다. 맞는 순간에 막대·숫자를 갱신한다.
  화면 탭은 남은 교환을 빠르게, 길게 누르기는 막 끝까지 건너뛴다.
- 세 순간
  1. **합:** 양쪽이 가운데로 달려가 부딪친다. 주사위 숫자가 머리 위로 튀고, 이기는 쪽 타격 순간에 짧은 멈칫(히트스톱)과 카메라 흔들림, 불꽃이 나온다. 진 쪽은 밀려나고 맞는 동작을 한다. 일방 공격·방어·회피도 각자 동작이 있다.
  2. **쓰러짐과 책:** 체력이 0이 된 적은 무너지며 조각(종이·파편)으로 흩어지고, 그 자리에 책이 빛나며 떨어져 바닥에 놓인다. 책 표지는 그 손님의 표지 그림(`bookCoverSrc`)이다. 이 손님이 책이 되는 승리면 마지막 책 낙하를 조금 길게 보여 준다.
  3. **강한 스킬:** 책장 등급이 오를수록 연출이 커진다.
     - N: 기본 타격
     - R: 이펙트 색과 양 증가
     - SR: 짧은 클로즈업과 주변 어둡게
     - SSR: 화면 어둡게, 카메라 클로즈업, 감속, 큰 이펙트

     전용 연출은 책장 id로 따로 등록하고(`stage.fx.register(pageId, fn)`), 없으면 등급 연출을 쓴다.
- 소리: 타격·합·책 낙하에 CC0 효과음을 붙인다(생동감에 크게 작용, 빌더 판단). BGM은 기존 `assets/audio/` 그대로 쓴다. 설정에서 끌 수 있다.
- 흐트러짐에는 비틀거리는 동작과 머리 위 표시, 정답/오답에는 짧은 무대 반응(빛, 흔들림)을 준다. 규칙 결과는 코어 값을 그대로 보여 준다.

### 5-3. 층 무대 = 데이터
`FLOORS`의 각 층에 `stage`를 둔다. 없으면 기본값을 쓴다.
```js
{ id:"crime", name:"범죄학의 기초", stage:{ mood:"lamp", accent:"#d9a35a", props:["scales","candles"] } }
```
- `mood`: `"lamp"`(등불 서고) | `"moon"`(달빛 열람실). 나중에 분위기가 늘면 여기에 추가한다.
  분위기 하나 = 배경색, 안개, 주변광, 주광, 역광, 타격 빛 색, 먼지 색, 등불 유무(시안 값에서 출발).
- `accent`: 층 포인트 색(책장 일부 책, 바닥 테두리, 소품 빛).
- `props`: 공용 소품 상자에서 고른다(저울, 촛대, 모래시계, 지구본, 시계, 책 더미, 두루마리, 랜턴 등, CC0). 무대 가장자리 정해진 자리에 놓는다.
- 처음 값: crime·criminal-law = lamp, memory·cognition = moon.
- 새 층 추가 = 이 한 줄. `docs/content.md`의 새 손님 추가 순서에 "층 무대 한 줄 정하기"를 넣는다.

### 5-4. 캐릭터
- 사서와 손님 모두 같은 CC0 리깅 캐릭터 몇 종에서 고르고, 색·소품·크기로 구분한다. 손님 데이터에 이미 있는 `archetype`, `palette`, `accessory`를 그대로 쓴다.
- 우두머리는 조금 크게, 따르는 적은 조금 작게(깊이 원근). 캐릭터 크기는 키우지 않고 여백으로 정리한다(옛 규칙).
- 3:3 배치: 사서는 왼쪽, 적은 오른쪽, 가운데는 비운다.

### 5-5. 전투 정보 UI (DOM, 무대 위)
- 옛 결정의 구성 요소를 새 모양으로 다시 만든다: 체력·흐트러짐 막대, 주사위(속도), 대상 화살표, 손패, [개막], 상태판, 문제 패널.
- 겹침 검사(`tests/overlap-check.mjs`)를 새 DOM에 맞춰 다시 만든다. 844×390, 390×844에서 0건이어야 배포한다.

### 5-6. 평면 화면 (이번 범위에서 최소한)
- 층 고르기 → 손님 고르기 → 전투 → 결과(책·기프트) → 다시. 덱 편성·도서관·계시는 이번 범위에서 최소 동작만 한다(빌더 판단).
- 결과·소각 안내는 80% 이상 불투명한 검은 전체 화면이나 별도 카드로 보여 준다(옛 결정).

### 5-7. 테스트
- 규칙 테스트 4개(`core`, `libs`, `mbdata`, `sim`)는 계속 통과해야 한다.
- 새로 만들 것
  - 무대 이벤트 순서 테스트: 교환마다 `play`가 차례로 불리고, 빨리 감기·건너뛰기가 된다.
  - 층 무대 기본값 테스트: `stage`가 없는 층도 무대가 그려진다.
  - 겹침 검사
  - 가로·세로 스크린샷
- 휴대폰 성능 확인: 실제 기기 대신 Chromium의 CPU 감속으로 프레임을 잰다(참고용).

## 6. 빌더에게 맡긴 것
- 에셋 팩을 정확히 무엇으로 할지(라이선스 확인 후), three.js 버전, 파일 나눔.
- 카메라 각도와 캐릭터 배치의 세부 수치(시안의 옆에서 살짝 내려다보는 각도에서 출발).
- 동작 타이밍(합 1.0초 안팎, 최대 1.6초라는 옛 값에서 출발).
- 전용 연출을 줄 SR·SSR 책장 고르기: 큐 양에게 나중에 묻는다. 그 전에는 등급 연출만 쓴다.
